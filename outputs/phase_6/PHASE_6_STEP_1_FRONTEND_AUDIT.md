## 9. Critical Scientific & Presentation Constraints

### Constraint 1: Disambiguation of Three Distinct Confidence Metrics
The frontend must **NEVER** combine or collapse confidence into a single generic field:
1. **`firms_confidence` (NASA FIRMS VIIRS Sensor):**
   - Values: `h` (High), `n` (Nominal), `l` (Low).
   - Meaning: Radiometric certainty from satellite instrumentation that a real thermal emission exists on Earth (vs cloud reflection, sun glint, sensor noise).
   - UI Label: **"Satellite Sensor Confidence"**.
2. **`max_probability` (Random Forest Winning Probability):**
   - Values: `0.0000` – `1.0000` (e.g. `0.9254` = `92.5%`).
   - Meaning: Direct mathematical softmax/tree probability assigned to the winning class.
   - UI Label: **"Winning Probability"**.
3. **`ml_confidence` (Categorical Tier):**
   - Values: `HIGH` (≥ 0.75), `MEDIUM` (0.50 – 0.74), `LOW` (< 0.50).
   - Meaning: Operational decision tier derived from winning probability.
   - UI Label: **"ML Model Confidence"**.

### Constraint 2: Strict Adherence to 3-Class Production ML Model
- The production Random Forest model predicts **exactly 3 classes**:
  1. `Industrial Thermal Activity`
  2. `Agricultural Burning`
  3. `Natural / Wildfire / Other`
- The frontend must **never fabricate 6-class ML predictions**.
- The 6-class taxonomy (e.g., `Persistent Industrial Source`, `Episodic Industrial Activity`) belongs strictly to the **Human Ground Truth Validation** study. If an event has `has_human_validation == true`, that label is displayed as an expert ground-truth validation badge, while the ML card reports `Industrial Thermal Activity`.

### Constraint 3: Accurate Sentinel-2 Optical Presentation
- Sentinel-2 MSI (MultiSpectral Instrument) operates in optical and near-infrared wavelengths (10m–20m resolution).
- **It does NOT detect thermal infrared radiation or fire plumes.** Thermal detection is strictly the domain of 375m VIIRS.
- Sentinel-2 provides supporting surface evidence (pre/post vegetation vigor via NDVI, surface scar via dNBR).
- When optical data was rejected due to cloud cover (`pre_observation_status == "CLOUD_REJECTED"`), the UI must display a clear, scientifically accurate message: *"Optical imagery obstructed by cloud cover during satellite overpass."*

### Constraint 4: Mandatory Disclaimer
Every prediction card and inspector drawer must display:
> *"Prediction is an algorithmic ML estimate. It is not ground truth."*

   - FastAPI Backend runs at `http://127.0.0.1:8000` (or `http://localhost:8000`).
   - Frontend dev server runs at `http://localhost:5173` (standard Vite default).

   - Add FastAPI `CORSMiddleware` with `allow_origins=["http://localhost:5173", "http://127.0.0.1:5173", "http://localhost:3000"]`, `allow_credentials=True`, `allow_methods=["*"]`, `allow_headers=["*"]`.
   - Alternatively, configure Vite `server.proxy` in `vite.config.ts`:
     ```ts
     server: {
       proxy: {
         '/api': {
           target: 'http://127.0.0.1:8000',
           changeOrigin: true,
         }
       }
     }
     ```

   - Requests to `POST /api/v1/predict` must pass `X-API-Key: test-api-key-phase5c` (configurable via `VITE_API_KEY` in `frontend/.env`).

   - Load `dashboard_events_633.csv` on application startup using `PapaParse` with worker thread parsing.
   - 633 records parse in < 30 milliseconds.
5. **No Model Direct Loading:**
   - Frontend must never import `.joblib` files or Python runtimes.

## 13. Risks & Potential Conflicts with Teammate Work

1. **Unsynchronized Parallel Frontend Work:**
   - *Risk:* If a teammate has started a frontend on a private branch or external repository using a different framework (e.g. Next.js vs Vite), creating an incompatible setup could cause merge conflicts.
   - *Mitigation:* Isolate all frontend code cleanly in a self-contained `frontend/` directory. Do not alter existing root configuration files or Python packages.
2. **CORS Pitfall:**
   - *Risk:* Browsers will fail live inference calls with `Cross-Origin Request Blocked` if CORS is omitted from `main.py` and no proxy is configured.
   - *Mitigation:* Document the exact CORS configuration needed in `src/api/main.py` and use Vite dev proxy as a seamless fallback.
3. **Column Conflation / Renaming:**
   - *Risk:* Teammates might attempt to rename CSV columns or combine the 3 confidence metrics into one.
   - *Mitigation:* The data schema in `dashboard_schema_design.md` and `DASHBOARD_DATA_DICTIONARY.md` is strictly frozen. TypeScript interfaces will enforce exact column naming.
4. **Target Leakage:**
   - *Risk:* Teammate UI forms might accidentally send `human_ground_truth_class` to `/api/v1/predict`, causing the backend to throw HTTP 422 `LEAKAGE_FIELD_DETECTED`.
   - *Mitigation:* The live prediction payload constructor must strictly filter input to the 36 baseline feature whitelist.
